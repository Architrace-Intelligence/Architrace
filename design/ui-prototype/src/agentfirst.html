Design principles · MVP

Agent-first, before the agent

The MVP ships without any AI. Its shape is still chosen so that an AI agent can take the wheel later without a redesign: one place to ask, one place to answer, stable addresses for everything and evidence under every claim.

2 · The context rail is the agent's seat

One card shape for rules today and narrative tomorrow

The right-hand rail reacts to what is selected: an environment, a node, a dependency, a comparison. Every card has the same four slots. Rules, diffs and the snapshot series fill them now; an LLM writes into the same slots later and nothing else changes.

highpostgresql/orders is used by 2 services
orders-service owns the schema; reporting-service reads it directly. A schema change in one breaks the other without any contract in between.

3 · Everything is addressable

Every view is a URL and every URL is an API call

Environment, filters, time and selection live in the URL; node ids never contain the environment. An agent, a script or a colleague can point at exactly what you see, and the JSON button shows the Query API request behind the screen.

UI  /env/PROD/map?at=live&domain=orders&node=service:orders/orders-service API GET /api/v1/environments/PROD/services/service:orders%2Forders-service UI  /drift?left=DEV&right=PROD&view=map API GET /api/v1/diff/environments?left=DEV&right=PROD
4 · Evidence before verdict

No claim without the rows behind it

Findings show the path, the calls and the window. Drift shows which side has what. Metrics are never part of drift, and traffic volume is never an argument. An agent that later speaks for the product cites these rows instead of asserting.
